## 一、最终产品形态

用户只看到一个研究应用：`agent-research`。用户输入研究问题，可以附加本次会话的
参考文件，然后启动研究、查看实时进度、阅读带证据的结论，并下载研究报告。

用户不需要选择或理解以下内部概念：Profile、Runtime、tutorial、showcase、mock、
fixture、Provider 类名、SDK 名称和评测分区。tutorial/showcase 已从生产装配和前端
删除，只允许通过明确命名的测试工厂构造。凭据无关的确定性研究 demo 仅用于浏览器
验收 schema 3.0 产品链路，不能接入默认应用或成为用户可选模式。

## 二、能力分级

| 能力 | 是否开始任务的前提 | 页面名称 | 不可用时的行为 |
|---|---:|---|---|
| OpenAI-compatible 研究模型 | 是 | 研究模型 | 返回结构化 `503`，不创建任务 |
| 会话文件工作区 | 是 | 会话文件 | 返回结构化错误，不创建任务 |
| Tavily 网络检索 | 否 | 实时网络检索 | 继续研究，并显示限制说明 |
| 只读 MySQL | 否 | 结构化数据 | 继续研究，并显示限制说明 |
| Qdrant Local + FastEmbed | 否 | 本地知识库 | 继续研究，并显示限制说明 |

健康检查只描述配置和本地可用性，不发起模型、搜索、SQL 或 embedding 请求。浏览器
永远不接收 Provider 密钥、绝对路径、原始 Provider 响应或异常堆栈。

## 三、三阶段实施顺序

### 阶段 1：LLM + Web + 上传

目标是先打通最小真实研究旅程：OpenAI-compatible 模型、实时网络检索、线程隔离的
多文件上传、WebSocket 进度，以及 JSON/Markdown/PDF 报告。

主要工作：

- 建立统一配置、能力注册和任务准入；
- 建立 OpenAI-compatible 模型适配层，不在初始化时请求模型；
- 将网络结果和上传文件内容转换为统一来源、证据和引用；
- 用 DeepAgents 主 Agent 和按能力启用的专家 worker 完成研究；
- 由应用程序统一生成报告，模型不能自行写报告文件；
- 前端替换为中文优先的单一研究工作台。

阶段退出条件：注入假模型和本地适配器后，一次带问题和上传文件的任务能够完成
WebSocket 闭环，生成一个经过校验的研究文档和完整三件报告；聚焦后端、前端、静态
检查和安全检查全部通过。真实 Provider 验收另需单独授权。

当前进度：上传到 WebSocket 的线程隔离闭环已经由注入式离线运行时证明，完整后端、
前端、静态、安全和构建门禁已经通过；fake/local 桌面与移动浏览器检查也已完成，
Stage 1 离线验收通过。真实 Provider 验证不属于该离线门禁。

### 阶段 2：MySQL + 本地知识库

目标是在不提高任务最低启动条件的前提下，加入结构化数据和本地知识证据。

主要工作：

- 复用只读 SQL 策略，增加表白名单、单语句、行数和超时限制；
- 将 MySQL 行转换为稳定的行定位器；
- 使用 Qdrant Local + FastEmbed 做非写入式就绪检查和受限 Top-K 检索；
- 将知识 chunk 转换为包含 collection、document、chunk 的稳定定位器；
- 前端区分“已使用、未使用、不可用、已降级”四种来源状态；
- 验证 Web、MySQL、本地知识库在 ready/unavailable/degraded 组合下都不会伪造证据。

阶段退出条件：每个可选来源要么贡献经过校验的证据，要么产生明确限制；自动化套件
不访问外部网络、不使用真实凭据。

### 阶段 3：完整引用、报告和失败语义

目标是让所有输出表面共享同一个可信研究文档，并清理用户可见的迁移残留。

主要工作：

- 模型只能引用已经存在的 evidence ID，不能创建来源或定位器；
- 使用 `GET /api/research-results?thread_id=...` 作为标准结果入口；
- API、WebSocket 完成事件、React、引用 JSON、Markdown 和 PDF 使用相同身份；
- 明确表达 unsupported、unavailable、unused、cancelled、model-failure、delivery-failure；
- 对 rate-limit/unavailable 最多重试一次，不重试认证、校验、SQL 策略和取消；
- 保证每个任务只有一个终态事件，报告失败不发布残缺文件；
- 完整离线门禁通过后删除旧前端模式分支，并以删除门槛测试持续防止回归；
- tutorial/showcase 仅保留为内部测试适配器，最终删除仍需单独的兼容测试退出门槛。

阶段退出条件：完整后端、前端、静态、安全和跨表面一致性门禁通过；成功、降级、
失败、取消各有正确终态；没有用户可见 Profile/Runtime 分支。真实 Provider 证据
仍然需要单独授权和单独证据记录。

## 四、前后端共同契约

后端负责能力快照、任务准入、来源适配、证据收集、声明校验和原子交付。前端负责
一个会话 UUID、一个 WebSocket、多文件上传、能力驱动的开始条件、实时阶段、终态
保护、结果读取、引用展开、限制说明和报告下载。

研究进度对用户显示为五个阶段：

1. 正在分析研究问题
2. 正在收集资料
3. 正在核对证据
4. 正在组织研究结论
5. 正在生成报告

研究结论中的每个声明都必须能展开到证据，再展开到稳定来源定位器。没有证据的
内容必须标记为未得到支持，不能显示成带来源的结论。

## 五、安全和授权边界

- 自动化测试只能使用假模型、假 Provider 或本地确定性适配器；
- 本阶段不授权真实 LLM、Tavily、MySQL、外部数据、部署、推送、tag、发布；
- 上传路径和报告路径必须保持线程隔离且禁止目录穿越；
- SQL 始终只读；检索内容一律视为不可信数据，不能改变系统指令；
- 交付要么完整生成引用 JSON、Markdown、PDF，要么清理临时文件并报告失败；
- 不声称真实质量、准确率、延迟、成本、SLA 或生产就绪，除非另有授权测量。

## 八、后续设计详述

### S3-3：跨表面身份与安全一致性（已验证实现基线）

这一包解决的是“同一份研究结果在不同出口是否仍是同一份结果”。服务器先校验并冻结
`ResearchDocument`，再从该文档生成 citation JSON、Markdown 和 PDF；WebSocket 的
`report_created` 与 `task_completed` 只携带该文档的身份摘要；前端读取结果后重新计算
摘要，并在与终态事件不一致时拒绝展示报告。来源、定位器、evidence、claim、线程归属、
引用哈希和固定三件 artifact 集合都必须在服务器和浏览器边界重新验证。

安全覆盖必须包括：原始 Provider 片段、HTML/script、token 形文本、绝对路径、带凭据的
URL、禁止的 URL query 参数、超长 quote、目录穿越 artifact 名称，以及损坏或缺失的结果。
这些输入要么被拒绝，要么只以经过约束的安全文本出现；不得依赖“脱敏后变短”绕过原始
长度限制。该包的聚焦后端/前端回归、静态检查和 diff 检查已通过；legacy 退出和完整
离线门禁和 fake/local 浏览器验收均已完成，S3-3 已纳入 Stage 3 离线验收。

### S3-4：失败、降级、取消与重试矩阵（已验证实现基线）

该包把失败语义固定为可观察的产品行为，而不是把异常直接透传给浏览器。已验证矩阵覆盖：
必需能力缺失、模型认证/超时/限流/不可用、可选 Web/MySQL/知识源在任务前后失败、上传
读取失败、取消竞态、慢 WebSocket 消费者和交付写入失败。每一行都要明确准入结果、是否
继续、限制说明、最终安全消息、artifact 清理和唯一终态事件。

只允许对瞬时限流或 Provider 暂时不可用最多重试一次；认证、输入校验、SQL 策略违反和
取消不得重试。失败或取消不能留下可下载的残缺报告，`TaskRegistry` 仍是唯一终态事件
所有者。模型、上传和交付失败使用固定安全错误码；可选来源继续以 limitation 降级；取消、
慢消费者、旧报告和临时 artifact 清理均已有责任边界覆盖。该结论只表示 S3-4 实现基线已
验证；S3-5 的代码退出、完整离线门禁和 fake/local 浏览器验收已经完成，Stage 3
离线验收通过。

### S3-5：旧产品分支退出（已完成）

删除门槛测试和全局搜索已经把用户可见遗留分支与批准保留的内部测试适配器分开。
生产 `create_app()` 只装配 `ResearchApplication`，旧工作台模块已经删除，默认健康响应、
前端入口和研究代码不再提供 Profile/Runtime 分支；tutorial/showcase 仅能通过测试支持
目录中的明确工厂构造。完整凭据无关后端回归、前端测试、类型/静态检查、生产构建和
差异检查已经通过。

内部确定性 schema 3.0 harness 已证明中文单一工作台、五项能力、上传、WebSocket 进度、
Web/MySQL/知识库/上传来源覆盖、声明与证据展开、定位器、标准结果身份、三件报告以及

据此 accepted；真实 Provider 可用性仍不在该结论内。

### S3-6：单独授权的真实 Provider 验收

这是独立的证据包，不是离线实现的默认步骤。每个外部系统分别获得授权后，才可进行最小
模型 smoke、受限 Web 查询、授权的只读 MySQL 查询、本地知识检索和组合运行，并记录安全
元数据、定位器与失败语义。结果只能支持“该 Provider 在该配置和时间点可用”的声明，不能
推导准确率、质量、延迟、成本、SLA、生产就绪、发布或部署结论。

### 文档与验收关系

ADR 记录为什么收敛到单一产品；批准设计记录系统应该如何工作；Phase 10 文档记录用户
价值与阶段出口；实施计划记录包顺序、文件责任和验证步骤；本蓝图提供中文阅读入口；
`phase-status.md` 只记录当前事实。设计确认、实现基线、聚焦测试通过和阶段验收是四个
不同状态，不能互相替代。
